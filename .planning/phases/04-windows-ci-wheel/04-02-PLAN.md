## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tag name -> shell (release step) | github.ref_name reaches a run: block — the classic Actions injection surface |
| GITHUB_TOKEN -> fork Releases | the only privileged write in the phase; scope creep here is an Elevation threat |
| cibuildwheel/delvewheel supply chain -> shipped binaries | the action and its transitive tooling build what users pip install |
| workflow triggers -> publish path | who can cause a Release to be created |
| artifact provenance | which wheels the release job is allowed to publish |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-04 | Elevation | GITHUB_TOKEN overprivilege on the publish path | high | mitigate | Workflow top-level permissions: {}; contents: write declared ONLY on the release job (job-scoped, the release.yaml id-token precedent); build/clean jobs run at the workflow's default (no write) |
| T-04-05 | Injection | tag name interpolated into the release run: block | high | mitigate | TAG reaches the script exclusively via env indirection (env: TAG: github.ref_name; script references "$TAG"); no ${{ }} interpolation inside any run: block |
| T-04-06 | Tampering | release publishing wheels not built by this run | high | mitigate | release job consumes only same-run artifacts (actions/download-artifact within the run, needs: clean_smoke); no URL downloads, no run-id inputs; the gate and the publish share one provenance chain |
| T-04-07 | Tampering | malicious PR triggering the publish pipeline | high | mitigate | win-wheels.yaml triggers are tag pushes + workflow_dispatch only — pull_request and branch pushes cannot start it; pushing tags to the fork requires collaborator push access; the clean gate runs before release regardless |
| T-04-08 | Repudiation | wheel integrity untraceable after publish | medium | mitigate | --generate-notes ties the Release to the exact commit; asset sha256s are recorded in 04-CI-VALIDATION.md (plan 04-03) with the delvewheel import-table evidence (no msvcrt.dll, no vendor DLLs — CLAUDE.md wheel-audit anti-pattern closed) |
